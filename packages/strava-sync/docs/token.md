# Token

`strava-sync` needs 3 variables, in the environment or in a `.env` file:

```dotenv
STRAVA_CLIENT_ID=2845
STRAVA_CLIENT_SECRET=c3d62caed3sjf4vdjsb096d010d81f52a17ac5
STRAVA_TOKEN={"access_token":"ya...J0","refresh_token":"1..mE","expires_at":1581439030,"expires_in":21600}
```

Run the following command at the root of your project to generate them:

```shell
npx strava-sync token
```

It asks for the Client ID and Secret of your [Strava application](https://www.strava.com/settings/api), opens Strava to authorize it, and writes the variables to your `.env` files. When you have several `.env` files for different environments, it writes them at the end of each one. Add them to your `.gitignore`, since they hold sensitive information.

## What the token can read

The command asks Strava for the `read_all`, `activity:read_all` and `profile:read_all` scopes. The token can then read your private activities, your full profile and your private routes. Without `read_all`, Strava leaves the private routes out without any error.

A token generated by an earlier version of the command lacks `read_all`, and refreshing a token keeps the scopes it was granted. Run the command again to get the private routes.

## Refreshing the token

Strava access tokens last 6 hours. The client refreshes an expired one and calls `onTokenRefresh` with the new token, which you should keep. `persistTokenToEnvFiles` rewrites `STRAVA_TOKEN` in the `.env` files that already hold it, and the command line does it for you.
